# Референс: SIATRA (siatra-shopiframe.framer.website)

Разбор тёмного Framer-шаблона мебельного e-commerce. Всё ниже снято с живого сайта 16.09.2026
(браузер 1280×633, страница 7588 px): снимки экрана, вычисленные стили, анимации — из JSON
`__framer__appearAnimationsContent`, который Framer вшивает в HTML.

Методика: реальный браузер (Chrome), прокрутка по секциям со снимками, `getComputedStyle`,
разбор вшитых стилей/скриптов. Что не удалось измерить — отмечено явно (см. «Ограничения»).

## 2. Поведение шапки при скролле

- Вся шапка **fixed** и прозрачная: маркиза на `top: 0` (56 px), nav под ней на `top: 56` (80 px),
  `background-color: rgba(18,19,20,0)`.
- **Фон не появляется, blur не включается, шапка не прячется**: значения computed-стилей одинаковы
  на scrollY = 0 / 1500 / 3000 / 4000 / вверх. На всех снимках (включая подвал) маркиза и меню
  видны на своих местах.
- Контент проезжает **под** шапкой (фото и заголовки просвечивают сквозь неё) — это и есть
  основная фишка: прозрачный слой поверх тёмной страницы.
- Единственное движение шапки — стартовое: и маркиза, и nav въезжают сверху (`y: -150 → 0`)
  с задержкой 1.7 s (см. ниже).
- Никакого «липкого» состояния/смены варианта при скролле нет.

## 3. Появление блоков: это НЕ scroll-reveal, а загрузочная хореография

Важное наблюдение: у шаблона **нет** появления блоков «по мере прокрутки». Все reveal-эффекты —
`Appear`-анимации, которые запускаются **один раз при загрузке страницы** и разведены по времени
задержками. Проверено: при прокрутке в секции товаров ни один из 187 узлов не менял transform/opacity,
строки каталога в кадре статичны, отдельных «появлений» ниже уровня сгиба не обнаружено.

Точные параметры (из вшитого JSON, значения as-is):

| Элемент | Стартовое состояние | Переход |
|---|---|---|
| Маркиза, nav, ещё 2 верхние полосы | `opacity 0.001`, `y -150` | **tween, 0.6 s, delay 1.7 s**, ease `cubic-bezier(0.44, 0, 0.56, 1)` |
| Фото hero («BG Hero») | `opacity 0.001` | **spring duration 0.4, bounce 0.2, delay 1.6 s** |
| Секция «Video» | `opacity 0.001` | spring duration 0.4, bounce 0.2, **delay 1.0 s** |
| Метка «©18-25» | `opacity 0.001`, `y 40`, `rotate -3°`, `perspective 1200` | **spring stiffness 205 / damping 30 / mass 1, delay 1.8 s** |
| Текст справа в hero | `opacity 0.001` | spring duration 1, bounce 0.1, delay 1.8 s |
| Кнопка hero | `opacity 0.001` | spring duration 1, bounce 0.1, **delay 2.0 s** |
| Строки каталога + описания | `opacity 0.001` | **spring stiffness 360 / damping 60, delay 0** |
| «Learn more about us» | `opacity 0.001` | spring 1 s, bounce 0.1, delay 0.7 s, финал — `opacity 0.8` (не 1) |
| Водяной знак «SIATRA» в подвале | `opacity 0.001` | spring 1.1 s, bounce 0.1, delay 0.9 s |

Что из этого важно перенести:

1. **Всё проявляется только прозрачностью** (`opacity 0.001 → 1`), кроме верхних полос: те единственные,
   кто двигается (сверху вниз на 150 px). Никаких масштабов, сдвигов картинок и параллакса.
2. **Stagger реализован вручную задержками** (0 → 0.7 → 0.9 → 1.0 → 1.6 → 1.7 → 1.8 → 2.0 s),
   а не общим механизмом «каждая следующая карточка +100 мс». Полная хореография первого экрана
   занимает **~2.6 s** после старта (первый контент — через 0.7 s, последний — через 2.0 s + 1 s пружины).
3. **Два типа движения**: tween `cubic-bezier(0.44, 0, 0.56, 1)` (мягкий ease-in-out) для шапки/маркизы
   и **spring** для всего остального. Пружины заданы либо парой `stiffness/damping` (205/30 — мягкая,
   заметный доезд; 360/60 — быстрая и почти без отскока), либо `duration/bounce` (0.4/0.2 — лёгкий
   отскок; 1/0.1 — спокойная).
4. Пружины Framer рендерит как WAAPI-анимации с **линейной** функцией и плотной дискретизацией кривой —
   это то, что видно в `document.getAnimations()` (duration 1000 ms, ease linear, delay 2000 ms).
   В CSS это повторяется через `linear()` easing или cubic-bezier-приближение.

## 4. Hover-состояния

Прямо измерить hover не получилось: инструмент ввода браузера в этой сессии не отправляет события
мыши (`Input.dispatchMouseEvent` таймаутит даже на тестовой странице), синтетические
`pointerover/mouseover` Framer игнорирует. Поэтому ниже — то, что подтверждено разметкой и
скомпилированными вариантами шаблона, без домыслов:

- **Круговые кнопки-стрелки** (в строках каталога и в карточках товаров) в hover-варианте Framer
  получают `--border-color: rgb(117, 130, 81)` (оливковый акцент) и `opacity: 1` — то есть граница
  из нейтральной становится оливковой, а элемент «догоняет» полную непрозрачность.
- **Строки каталога** хранят цвет текста в переменной `--extracted-r6o4lv: rgba(255,255,255,0.35)`:
  в покое строка приглушена (35 % белого), в hover-состоянии выходит на полную непрозрачность —
  классический «dim list → hover brighten».
- Есть состояния `-pressed` (тот же `opacity: 1`) и `opacity: .5` для disabled.
- Встроенный компонент-кнопка использует `hover: { backgroundColor: rgba(0,0,0,0.05) }` (это про
  светлую кнопку промо-модалки).
- Атрибут `cursor` у карточек и кнопок — обычный (`auto`), «руки»/grab нет.

По снимкам видно, что фото товаров — основная площадь карточки (256×369 при фото ~256×300),
подпись снизу: название белым, цена серым, справа круглая кнопка-стрелка. То есть даже без hover
карточка читается как «фото + строка с ценой и переходом».

## 8. Что переносим в наш статичный сайт (HTML/CSS/JS), а что нет

### Переносится почти 1:1, дешево

1. **Палитра и токены** — просто CSS-переменные: `--bg:#131415; --bg-deep:#0E0F0F; --text:#CDD1C2;
   --accent:#758251; --muted:#898A87; --ghost:rgba(205,209,194,.08)`. Плюс правило «заголовки белые,
   тело — шалфейное».
2. **Типографическая шкала** — 120/72/48/36 px для заголовков с `letter-spacing: -0.06em;
   line-height: 0.9`, тело Inter 16 px с `letter-spacing: -0.02em; line-height: 2`. Подключаем Inter и
   Bebas Neue через Google Fonts (у нас сейчас в проекте свои шрифты — это отдельное решение).
3. **Fixed-шапка поверх контента, без смены фона** — `position: fixed; top: 0; background: transparent`.
   Самое простое и самое «дорогое» по впечатлению.
4. **Маркиза-полоса сверху** — CSS `@keyframes` c `translateX` (в референсе статичный повтор, но
   бегущая строка — тот же визуальный приём и делается в 10 строк).
5. **Загрузочная хореография (stagger)** — CSS-анимации с задержками или один JS-цикл, выставляющий
   `animation-delay` из массива. Значения берём как в таблице раздела 3
   (`cubic-bezier(0.44,0,0.56,1)` для шапки, задержки 0 → 2.0 s для остального). Пружины
   аппроксимируем: `cubic-bezier(0.22,1,0.36,1)` (ease-out-quint) для мягких, либо современный
   `linear()` с точками пружины, либо `transition` + `scale(1.02)` для «отскока» кнопок.
6. **Призрачный гигантский заголовок** — обычный текст с `color: rgba(205,209,194,.08)` и
   `font-size: clamp(...)`.
7. **Строки каталога** — `<ul>` со строками: имя слева (крупно), описание справа (мелко), разделитель
   `1px rgba(255,255,255,.35)`, круглая кнопка-стрелка; в покое текст 35 % непрозрачности,
   на `:hover` — 100 % + оливковая рамка кнопки. Это ровно CSS-переходы, Framer не нужен.
8. **Карточка товара** — фото сверху (пропорция ~4:3, `object-fit: cover`), подпись: название/цена +
   круглая кнопка-стрелка. Плюс `overflow: hidden` на карточке для зум-эффекта фото на hover
   (`transform: scale(1.04)` у `img`).
9. **Сетка отзывов** — CSS `columns: 3` (masonry без JS) с карточками: цитата, аватар, имя, роль.
10. **Подвал** — 5 колонок на grid + гигантский словесный знак, «обрезанный» по низу
    (`overflow: hidden; font-size: clamp(120px, 30vw, 420px); color: rgba(255,255,255,.06)`).
11. **Промо-модалка при загрузке** — реализуемо (`<dialog>` + флаг в `localStorage`, чтобы не бесила).
12. **Уважение к `prefers-reduced-motion`** — в Framer это не «из коробки» на все эффекты; у нас
    добавляем отключение stagger/пружин.

### Переносится, но требует работы / компромиссов

13. **Точные пружины Framer.** CSS-`transition` со стандартными кривыми даёт «похоже, но не то».
    Варианты: `linear()` + сгенерированная кривая пружины (современно, 1 правило), либо мини-либа
    (motion/framer-motion в статичном билде), либо сознательно заменить пружины на tween
    `cubic-bezier(.22,1,.36,1)` и не страдать.
14. **Sticky-пиннинг секции.** В референсе секция товаров — `position: sticky; top: 160px` внутри
    высокой секции. Сама по себе липкость — одна строка CSS, но «проезд» карусели привязан к прогрессу
    прокрутки (`scroll` + `transform`), это уже JS на 20-30 строк и осторожность с мобильными.
15. **Горизонтальная карусель.** В шаблоне ряд карточек шире экрана, элементы управления отсутствуют,
    внутри `overflow: hidden` — то есть задумано перетаскивание/свайп. У нас проще и надёжнее:
    `overflow-x: auto` + `scroll-snap-type: x mandatory` (нативный свайп/тачпад) ± кнопки-стрелки.
16. **Видео-лайтбокс** (кнопка Play) — переносится только если у нас появится видео-файл или ссылка;
    сам оверлей с затемнением и плавным появлением — простой CSS+JS.
17. **Резкость фото.** Референс держится на профессиональных фотографиях. Наши текущие снимки другие
    по свету и стилю, поэтому «тот же приём» даст другой результат, пока не будет фото-контента.

### Не переносится (или не имеет смысла)

18. **CMS/Shopify-интеграция, корзина, чекаут, страницы товаров** — это Framer+Shopify-движок;
    в статичном сайте без бекенда это бутафория. Корзину/фильтры придётся делать отдельно.
19. **SSR-варианты по брейкпоинтам** (`ssr-variant hidden-*`): у нас это обычные media-запросы.
20. **Точный drag-инерционный скролл Framer** (физика инерции, «магнит» к карточке) — заменяем
    нативным scroll-snap; 1:1 не нужно.
21. **Бейдж «Made in Framer»** и шаблонная промо-модалка «Get 15% Off Shopiframes» — к нашему бренду
    отношения не имеют.
22. **Магия «появления при скролле»**, которой от Framer обычно ждут, здесь и отсутствует — если мы
    добавим настоящие scroll-reveal эффекты, мы уже уйдём от референса (нужно осознанно решить).

## 9. Топ-3 приёма для внедрения

### 1) Первый экран: фото на всю ширину + огромный заголовок с плотным трекингом + микроподписи
**Что делаем:** hero-секция 100vh: фон — фото, поверх — заголовок 120 px (`letter-spacing:-0.06em`,
`line-height:0.9`), метка слева сверху (12-14 px, капс/разрядка), справа снизу короткое описание
(16 px, `line-height:2`, шалфей) и круглая кнопка-стрелка.
**Почему первым:** это 90 % впечатления от шаблона; стоит нам одну секцию HTML + ~30 строк CSS;
не требует ни Framer, ни JS; и сразу отличает нас от «обычных магазинов» с центрированным текстом.
**Дополнительный бонус:** загрузочная хореография (opacity-фейды с задержками 0 → 1.8 s) — даёт
ощущение «дорогого» сайта при нулевой цене реализации (CSS `animation-delay`).

### 2) Фиксированная прозрачная шапка + оливковая маркиза-полоса
**Что делаем:** `position: fixed; background: transparent` (без смены фона при скролле), а сверху —
56-пиксельная полоса с бегущей строкой акции капсом, оливковыми точками-разделителями и текстом
цвета шалфея.
**Почему:** вторая по силе деталь «тёмного премиума» (контент проезжает под шапкой — эффект
дорогой вёрстки при трёх строках CSS), а маркиза — бесплатный рекламный слот под акции/доставку.
**Дополнительно:** оливковый акцент `#758251` из маркизы дальше переиспользуется в hover-границах,
бейджах и линках — так палитра становится связной, а не «чёрный сайт с одной зелёной точкой».

### 3) Каталог коллекций строками: крупное имя + приглушённый текст + круглая кнопка-стрелка
**Что делаем:** вместо сетки карточек — список строк высотой ~190 px: слева огромное название
(64 px), справа мелкое описание (35 % непрозрачности, на hover — 100 %), тонкий разделитель
`1px rgba(255,255,255,.35)`, в конце строки круглая кнопка-стрелка, граница которой на hover
становится оливковой.
**Почему:** это самый «не-магазинный» и самый узнаваемый приём референса — превращает скучный список
категорий в редакционную подачу; реализуется чистым CSS (`:hover`, `transition`), без библиотек.
**Дополнительно:** если понадобится «вау», тот же паттерн расширяется превью-картинкой, всплывающей
у курсора, — но это уже JS, и начинать стоит с базового hover.

**Что отложить:** пружины Framer 1:1, sticky-пиннинг карусели и drag-инерцию — эффектные, но дорогие
в отладке; выигрыш на фоне первых трёх пунктов небольшой. Видео-лайтбокс и промо-модалку — после
того, как появится контент.

## 10. Ограничения этого разбора

- Hover-состояния **не измерены напрямую** (ввод мыши в браузерной сессии недоступен): описаны по
  скомпилированным вариантам шаблона и разметке. Точные значения (масштаб фото, сдвиг стрелки) —
  под вопросом; в статичном варианте мы задаём их сами.
- «Прокрутка» маркизы и инерция карусели проверены косвенно: за 1.5-2 s наблюдения ни один элемент
  не менял `transform`, в кадрах положение повторов маркизы не менялось. Утверждать «маркиза точно
  бесконечно бежит» оснований нет.
- Разбор сделан на ширине 1280 px (десктоп-вариант). Мобильные варианты (`ssr-variant hidden-*`) в
  DOM присутствуют, но их тайминги/раскладка отдельно не снимались.
